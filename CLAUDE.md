# justread

A lightweight cross-platform desktop EPUB and PDF reader (Linux, macOS, Windows) in Rust.
The owner is learning Rust with this project: write idiomatic Rust and briefly
explain new language concepts when introducing them.

## Layout

Cargo workspace (`Cargo.toml` at the root, edition 2024, resolver 3):

- `epub-core/`: library. Parses EPUBs and serves their resources. No UI dependencies.
  - `book.rs`: `Book<R: Read + Seek>`, the public entry point (`Book::open`, `contents`, `read_bytes`, `media_type`, `warnings`), and `Contents` (metadata, spine, TOC; cloneable, no file handle) with `spine_index_of`, `toc_entry_for`/`chapter_title`, and size-weighted `progress`.
  - `opf.rs`: `META-INF/container.xml` → OPF path; OPF metadata/manifest/spine.
  - `toc.rs`: EPUB3 `nav.xhtml` (preferred), EPUB2 `toc.ncx` fallback.
  - `href.rs`: `Href::resolve(from_doc, href)`: percent-decoding, `#fragment`, `..`, and rejecting paths that escape the archive or remote URLs.
  - `xml.rs`: `roxmltree` helpers (match by local name, DTD allowed, BOM stripped).
  - `error.rs`: `EpubError` (`thiserror`) and `Result<T>`.
  - `search.rs`: `Book::search(query, limit)`: body text of each spine document (minus `<script>`/`<style>`), folded (whitespace runs → one space, per-char lowercase when it stays one char), non-overlapping matches → `SearchHit { spine_index, occurrence, before, matched, after }`. **`reader.js` re-implements the same text extraction and folding to find "occurrence n" in the page: change both together.** Documents that aren't well-formed XML are skipped (listed in `SearchResults::skipped`).
  - `progress.rs`: `BookKey` (hex SHA-256 of the file, so moved/renamed books keep their place), `Position { spine_index, fraction }`, and `ProgressStore`: one JSON file (`last_opened` + `books` keyed by hash), saved atomically (write `<file>.tmp`, `sync_all`, rename). A missing file is an empty store; an unparseable one is moved to `<file>.corrupt` with a warning, never overwritten. Unknown/missing JSON fields are tolerated (`#[serde(default)]`). `write_atomic(file, bytes)` is the shared atomic-write helper (also used for preferences).
  - `examples/info.rs`: CLI that prints metadata, spine and TOC.
- `reader-app/`: Dioxus 0.7 desktop app; the binary is named `justread` (`[[bin]]` in its Cargo.toml): `justread [book.epub]`. Bundle settings in `reader-app/Dioxus.toml`, icons in `reader-app/icons/` (generated by `make_icons.py`), Linux `.desktop` template in `reader-app/packaging/`. `reader-app/dictionary/`: `en-es.tsv.gz` (English Wiktionary subset, CC BY-SA, embedded with `include_bytes!`) and `build.py` that makes it from kaikki.org's wiktextract dump (stdlib only; commit both together; see its README).
  - `main.rs`: window config, loads preferences, registers the `epub` custom protocol, provides `SharedBook`, `SharedStyle`, `Startup` (CLI book, file locations, initial preferences) and `GoogleRequests` as contexts; warms `Dictionary::shared()` on a thread; `with_custom_event_handler` drives the `GoogleWindow`.
  - `storage.rs`: data directory (`directories` `data_local_dir`, overridable with `JUSTREAD_DATA_DIR`) holding `progress.json` and `preferences.json`; load/save that log errors instead of failing. If `progress.json` exists but can't be read, saving progress is disabled rather than overwriting it; a bad `preferences.json` just falls back to defaults.
  - `preferences.rs`: `Preferences { theme: Light|Sepia|Dark, font_scale: 60..=200 %, line_width: Narrow|Medium|Wide|Full, tap_to_translate: bool, pace_wpm: 80..=600, pace_word: bool }` (serde, `#[serde(default)]`) and `chapter_css()`, the stylesheet added to every chapter (the `jr-pace-word` rule is left out when `pace_word` is off, so reader.js's word highlight draws nothing). Light/100%/Full emit nothing so the book's design stays (except the always-on padding and the `jr-search`/`jr-lookup`/`jr-pace-line`/`jr-pace-word` highlight colors). Theme rules are prefixed with `:not(#_jr)` x3 (links/code x4) so they beat book rules scoped under an id (`#content a {… !important}`). Unit tested.
  - `pdf.rs`: PDF books. A PDF is one "chapter" (`viewer.html`, one spine item) whose page is `pdf-viewer/viewer.html` + `viewer.js`: PDF.js 4.10.38 (vendored `pdf.min.mjs` / `pdf.worker.min.mjs`, Apache-2.0, see `pdf-viewer/LICENSE`) renders the pages as one scrolling document. The viewer loads `reader.js` like an EPUB chapter, so translation, links, scrolling, Back/Forward and progress reuse the same code. The viewer sends `outline` (the TOC, pages as `#page-N` anchors) and its own `ready` (`window.justreadDeferReady` stops `reader.js` from reporting `ready` before the pages exist). Internal links are `<a href="#page-N">`, which `reader.js` reports like any in-book link. Text size is the zoom: the app sends `zoom {scale}` (font size / 100) on every change and when the page is ready, and the viewer re-lays out its pages at that width, keeping the reading fraction. Line width doesn't apply (no reflow). Not yet: search (no hits).
  - `protocol.rs`: serves `epub://book/<book-id>/<path-in-zip>` (Windows: `http://epub.book/...`) from the open book (`Source::Epub`, or `Source::Pdf` bytes with the viewer files) with the right Content-Type; injects `<link href="/__justread/reader.css"/>` + `<script src="/__justread/reader.js">` before `</head>` of documents only; serves malformed XHTML as `text/html`; error pages instead of panics. `SharedBook = Arc<Mutex<Option<OpenBook>>>`; `SharedStyle` holds the current chapter CSS served at `/__justread/reader.css` (`Cache-Control: no-store`). Error pages link it too, so they follow the theme.
  - `reader.js`: runs inside each chapter; postMessage bridge to the app. ←/→ turn a screenful (`turnPage`) and send `turn` only at the chapter's end/start; also sends in-book link clicks (with the clicking document's exact fraction/section, so Back returns there despite the scroll debounce), scroll fraction + current `section` (last TOC heading above 30% of the viewport, from ids sent by `track_sections` after `ready`), `shortcut` (Ctrl/Cmd +/−/0/F, Esc, Alt+←/→ and mouse side buttons = back/forward), `find_failed`, `pace_paused`, `lookup {text, before, after, rect}` (a clicked word via `caretRangeFromPoint`, or a mouse selection widened to whole words; `before`/`after` = rest of its sentence from `Intl.Segmenter` within the closest block) and `dismiss` (click off any word); receives `page`, `scroll_to*`, `restyle`, `track_sections`, `find` (highlight via `CSS.highlights` `jr-search`), `clear_find`, `mark_lookup`/`clear_lookup` (`jr-lookup`), `pace {playing, wpm}`. The bridge script adds the iframe's offset to a lookup's `rect` and the window size (`viewport`).
  - Restyling: changing a setting updates `SharedStyle`, saves `preferences.json`, and sends `restyle {version}`; `reader.js` loads `reader.css?v=N` next to the old link and, once loaded, removes the old one and restores the scroll fraction (no reload, no flash, same place in the text). The app chrome follows the theme via `data-theme` on `.app` (CSS variables in `style.css`).
  - Reading pacer (EPUB only; hidden for PDFs): the `pacer` section of `reader.js` highlights the current line (`jr-pace-line`) and word (`jr-pace-word`) and advances at `pace_wpm`, staying longer on long words, punctuation and block ends (`PACE` constants). It starts at the last clicked word, else carries on from its word if still on screen, else the first visible word. It auto-scrolls the line to 30% of the window, sends `turn` at the chapter end (or right away in a chapter with no words), and stops with `pace_paused` on a wheel, scroll key, click, or any scroll it didn't make. The app owns `pacing` (not saved): Space toggles it, `[`/`]` change the speed (also in the header's `Pacer` controls, whose ⚙ menu has the speed and "Highlight word" = `pace_word`; it and the "Aa" panel close each other), Esc stops it after lookup/settings/pacer menu/search, and `ready` of a new chapter re-sends `pace` while it runs.
  - `bridge.rs`: the app-side half (one long-running `document::eval`), `PageEvent` / `Command` serde enums.
  - `reader.rs`: `Reader` state and navigation rules (next/prev, go_to, jump, follow_link, go_back/go_forward, on_ready, on_scroll); unit tested, no UI code. Jumps (in-book links, TOC entries via `jump`, the first search hit shown per search) record the place left; Prev/Next and page turns don't.
  - `dictionary.rs`: `Dictionary` (parsed once via `OnceLock` from the embedded gzip, `flate2`) and `lookup(text, after)` → `Vec<Entry>`, most specific first: the longest phrase of the word (or a base form) + up to 3 following words of the sentence ("ran" + "out of" → "run out"), the text itself, then base forms (Wiktionary `=` links, then suffix guesses). Normalizes case, curly apostrophes, possessive `'s`. Unit tested.
  - `lookup.rs`: `Lookup` (clicked text, sentence parts, entries, position) and the `LookupPopup` component (`position: fixed`, placed by the pure, tested `popup_style`: below the word, or above it in the bottom 40%; 4 senses per entry + "N more"). Closes on ×, Esc (before search/settings), `dismiss`, and any scroll/chapter event; closing sends `clear_lookup`. Ignored when `tap_to_translate` is off.
  - `google.rs`: Google Translate (`translate_url`: `sl=en&tl=es`) in a plain tao window + wry webview, because Google sends `X-Frame-Options: SAMEORIGIN` and Dioxus windows hand every http(s) navigation to the system browser. Tao creates windows only inside the event loop: the popup fills `GoogleRequests` and spawns a self-waking task (waking a Dioxus task sends the loop an event; `request_redraw` doesn't on Linux), then `GoogleWindow::handle_event` creates the window once (Linux `build_gtk(default_vbox)`) or reuses it; `CloseRequested` hides it (Dioxus ignores close events of windows it doesn't own). Its `WebContext` is `<data dir>/google-webview`.
  - `history.rs`: browser-style back/forward stacks of `Position`s (in memory, per open book, at most `LIMIT` = 50); returning uses `Scroll::Fraction`. Unit tested.
  - `app.rs`: components (`App`, `BookHeader`, recursive `TocList`); `style.css` is inlined via `with_custom_head`. On open: hash the file, `Reader::restore` the saved position (applied as `Scroll::Fraction` once the chapter reports ready), record `last_opened`. A `use_effect` saves whenever `Reader::position()` changes (scroll events are debounced in `reader.js`, so roughly once per scroll stop). With no CLI argument the last book is reopened if it still exists.

## How an EPUB is read

- Never extract to disk; zip entries are read on demand via `ZipArchive::by_name`.
- `container.xml` `rootfile/@full-path` → OPF. Manifest hrefs resolve relative to the OPF's folder; nav/NCX hrefs relative to the nav/NCX file.
- All paths stored in `epub-core` types are decoded zip entry names (no leading `/`, no `%xx`).
- Problems that still leave a readable book (bad manifest href, broken TOC, missing `mimetype`) go into `Book::warnings()`. Only an unreadable container/OPF or empty spine is an error.
- Rendering: the current spine item is shown in an iframe at `epub://book/<book-id>/<path>`, so relative CSS/image/font links resolve natively. It is a separate scheme because Dioxus blocks every `dioxus://` navigation after the first page load, iframes included (`dioxus-desktop` `webview.rs`). The book id changes on every open (no stale cache, no cross-book reads).
- The iframe is cross-origin to the app, so the app never touches its DOM: everything goes through `reader.js` ⇄ `bridge.rs` postMessage. Fragments are scrolled by the chapter itself after it reports `ready` (or immediately if the document is already loaded).

## Commands

```bash
cargo fmt --all
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p epub-core --example info -- path/to/book.epub
cargo run -p reader-app -- path/to/book.epub   # or: dx serve -p reader-app --platform desktop
```

All three checks (fmt, clippy with `-D warnings`, tests) must pass before every commit.

Packaging (always from the workspace root; `desktop_template` in Dioxus.toml is resolved relative to the current directory):

```bash
dx bundle -p reader-app --desktop --release --package-types deb --package-types rpm --out-dir dist   # Linux
dx bundle -p reader-app --desktop --release --package-types macos --package-types dmg --out-dir dist # macOS
dx bundle -p reader-app --desktop --release --package-types msi --package-types nsis --out-dir dist  # Windows
```

CI: `.github/workflows/ci.yml` runs fmt/clippy/test on ubuntu/macos/windows-latest, then (not on PRs) bundles on each OS and uploads `dist/*` as artifacts; on `v*` tags a `release` job checks the tag equals `v<reader-app version>` and creates a GitHub Release with every file from the artifacts (`gh release create --verify-tag`, `contents: write`). `ci.yml` is also a reusable workflow (`workflow_call` input `release_tag`: the tag to check out and release; deliberately not an arbitrary ref). Release builds skip `rust-cache` (no installers built from a cache anything on main could have written). `.github/workflows/release.yml` (manual, `workflow_dispatch` with bump `patch|minor|major|current`) computes the version with `.github/scripts/next-version.sh`, edits `reader-app/Cargo.toml` + `cargo update --workspace`, commits "Release vX.Y.Z" to main, tags, pushes both atomically, then calls `ci.yml` with that tag. It calls CI instead of relying on the tag push because pushes made with `GITHUB_TOKEN` don't trigger workflows. Keep `actions/*` on their latest majors (Node 24). dx 0.7.10 gotchas: don't add `strip = true` to `[profile.release]` (dx's own strip step then fails on macOS, libLLVM.dylib not found); Windows installers use `webview_install_mode = DownloadBootstrapper` (dx's default embeds a ~170 MB WebView2 installer). `.gitattributes` marks `*.epub` binary so Windows checkouts don't rewrite fixture bytes (their SHA-256 is asserted). Keep the `dx` version equal to the `dioxus` crate version.

Use `JUSTREAD_DATA_DIR=<scratch dir>` when testing so the real `~/.local/share/justread/progress.json` isn't touched.

Verifying the UI on Linux: start the app with `WEBKIT_INSPECTOR_HTTP_SERVER=127.0.0.1:9334` and drive it through WebKit's remote inspector websocket (`/socket/1/1/WebPage`, commands wrapped in `Target.sendMessageToTarget`; `Runtime.evaluate` for DOM/state, `Page.snapshotRect` for screenshots). Avoid port 9222 (often a Chrome debugging port). The chapter iframe has its own execution context: send `Page.enable` + `Runtime.enable`, collect the `Runtime.executionContextCreated` contexts, and pass the frame's `contextId` to `Runtime.evaluate` (e.g. to read `CSS.highlights`). You can also verify through effects (progress, current chapter), or fake a message from the chapter with `dispatchEvent(new MessageEvent("message", {source: document.getElementById("chapter").contentWindow, data: {justread: {...}}}))` in the app page. `reader.js` itself can be exercised with real clicks on a local test page in the built-in browser (at the top level, `parent === window`). There is no xdotool on the dev machine (Wayland). The Google window is its own inspector page (`socket/1/<n>/WebPage`, listed at `http://127.0.0.1:9334/`). `dx serve` renames the binary (`justread-<hash>`), so stop it by PID. Release builds have the context menu and WebKit developer extras off (`with_disable_context_menu(!cfg!(debug_assertions))` in `main.rs`), but `WEBKIT_INSPECTOR_HTTP_SERVER` still exposes the page, so the same inspector approach works on `dx bundle` output.

## Conventions

- No `unwrap()`/`expect()` outside tests; a malformed book must never panic.
- `thiserror` errors in `epub-core`; `anyhow` in binaries/examples. Error variants that wrap a source don't repeat it in their message.
- Dependency versions are pinned exactly (`=x.y.z`). Check docs.rs or the crate source for the pinned version before using an API (Dioxus changes a lot between versions).
- Prefer integration tests against real fixture EPUBs (`epub-core/tests/`); small unit tests only for pure helpers like `href.rs`.
  - `tests/gutenberg.rs`: real public-domain books; `tests/broken.rs`: hand-made broken books; `tests/common/mod.rs`: shared helpers.
  - Fixtures and their sources are listed in `epub-core/tests/fixtures/README.md`. Hand-made fixtures are built from `tests/fixtures/hand-made/<name>/` by `hand-made/build.sh`; edit the folder, rerun the script, commit both.
  - Never commit commercial or copyrighted books as fixtures.
- Small modules, simple code, short comments explaining Rust concepts where they first appear.
- Linux build deps for the Dioxus app: `libwebkit2gtk-4.1-dev build-essential libssl-dev libxdo-dev libayatana-appindicator3-dev librsvg2-dev pkg-config`.
